# Лабораторна робота №2

## Варіант

Номер у списку групи: 12.

Розрахунок варіанта:

V = N mod 3

V = 12 mod 3 = 0

Отже, мій варіант - V = 0: Аналізатор логів серверів.

## Про проєкт

У цій лабораторній роботі реалізований аналізатор серверних логів у форматі Common Log Format.

Клас `LogAnalyzer` дозволяє:

- отримати всі унікальні IP-адреси
- знайти IP-адреси, які найчастіше зустрічаються в логах
- ігнорувати рядки, які не відповідають потрібному формату

## Використані технології

- Java 26
- Gradle
- Gradle Version Catalog
- JUnit 5
- Java Collections Framework
- IntelliJ IDEA

## Реалізація

У проєкті реалізований клас `LogAnalyzer`.

Він містить два основних методи.

### getUniqueIps

```java
public Set<String> getUniqueIps(List<String> logLines)
```

Метод приймає список рядків серверного логу та повертає множину унікальних IP-адрес.

Для зберігання результату використовується `Set`, тому одна й та сама IP-адреса не дублюється.

Рядки, які не відповідають очікуваному формату логу, ігноруються.

Якщо `logLines` дорівнює `null`, метод викидає `IllegalArgumentException`.

### getTopIps

```java
public List<String> getTopIps(List<String> logLines, int topN)
```

Метод підраховує кількість появ кожної IP-адреси та повертає список найчастіших адрес.

IP-адреси сортуються:

1. за кількістю появ у порядку спадання
2. якщо кількість появ однакова — у лексикографічному порядку

Якщо кількість знайдених IP-адрес менша за `topN`, метод повертає всі доступні адреси.

Рядки, які не відповідають очікуваному формату, не враховуються.

Якщо `logLines` дорівнює `null`, метод викидає `IllegalArgumentException`.

## Робота з логами

У проєкті обробляються серверні логи у форматі Common Log Format.

Приклад рядка:

```text
127.0.0.1 - - [10/Oct/2026:13:55:36 +0300] "GET /index.html HTTP/1.1" 200 1024
```

IP-адреса береться з початку коректного рядка логу.

Некоректні або неповні рядки ігноруються та не впливають на результат аналізу.

## Використання колекцій

У роботі використовуються стандартні колекції Java.

Для зберігання унікальних IP-адрес використовується `Set`.

Для підрахунку кількості появ IP-адрес використовується `Map`.

Для повернення відсортованого результату у методі `getTopIps` використовується `List`.

## Тестування

Для тестування використовується JUnit 5.

Тести перевіряють:

- отримання унікальних IP-адрес
- відсутність дублікатів у результаті
- правильний підрахунок частоти появ IP-адрес
- сортування IP-адрес за частотою
- лексикографічне сортування при однаковій частоті
- ситуацію, коли кількість IP-адрес менша за `topN`
- ігнорування некоректних рядків
- обробку `null` аргументів

## Gradle

Проєкт збирається за допомогою Gradle.

Для керування версіями залежностей використовується Gradle Version Catalog:

`gradle/libs.versions.toml`

JUnit 5 підключений через Version Catalog.

## Запуск тестів

Для запуску тестів на macOS/Linux:

```bash
./gradlew test
```

Для очищення попередньої збірки та запуску тестів:

```bash
./gradlew clean test
```

Для повної збірки проєкту:

```bash
./gradlew build
```

У разі успішного виконання Gradle виводить:

```text
BUILD SUCCESSFUL
```
